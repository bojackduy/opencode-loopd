# Competitor source architecture and reliability: prevalentWare/opencode-goal-plugin

## 1. What architecture and execution model does the competitor actually implement?

### Takeaway
This is a persisted, same-session goal-continuation plugin with a real TUI and two OpenCode API adapters. Its natural unit is one current goal per session, with multiple sessions represented in shared state; it is not, in the inspected execution path, a dedicated-child-session goal worker scheduler. [Entrypoints](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3766-L3770), [same-session delivery](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L554-L561), [goal creation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L981-L993).

Inspection date: 2026-10-18. All source links below pin that SHA. [Commit](https://github.com/prevalentWare/opencode-goal-plugin/commit/9c52be63da06829d55e3e0b7a6580223312765b1).

Goal creation stores a record and initializes usage, rather than provisioning a separate goal session. Existing task/subagent children are tracked to defer parent continuation; tracking children does not mean goals themselves are isolated child workers. - **Hooks and triggers:** v1 intercepts tool execution, commands, chat messages, message/system transforms, compaction and compaction-autocontinue; it drives continuation on `session.idle` or `session.status: idle`. v2 consumes a subscribed event stream and uses `session.execution.succeeded` (plus legacy idle compatibility) as a continuation boundary. Step completion is intentionally not an execution boundary; scheduled v2 work uses the host's `session.wait` barrier when available. [v1 hooks](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2163-L2266), [v1 idle dispatch](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2390-L2393), [v2 boundaries](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3021-L3039), [v2 wait](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2660-L2677).
- **Commands are slash commands, not OS-process facilities:** registered goal tools cover reads/history/listing, create/set/edit/plan/status/complete/unmet/stop/replace/clear. The inspected registry has no process-start/stdin/PTY/watch/await-command tools. Execution of project commands is left to host tools and the agent; do not confuse `/goal` command registration with a raw background-process manager. [Complete v1 registry](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2022-L2162), [v2 registry](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3575-L3763).
- **Actual TUI:** session sidebar shows objective, state, elapsed time, token usage, auto-continuations, checkpoint and stop/status text; a command opens a summary/action dialog. v1 and v2 have separate implementations. The UI consults tool-result snapshots/cache plus the persisted state file; file refresh uses inode/mtime/size checks every second and retains a last valid view after read failures. [Sidebar](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/tui.ts#L536-L628), [persistence reads](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/tui.ts#L419-L476), [v2 sidebar](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/tui.ts#L723-L795).

### Inferences
- **Product tradeoff:** same-session execution preserves the user's current context and agent selection with little ceremony, but does not itself isolate worker context or workspace writes from the interactive session. Cross-session listing is visibility, not proof of a centralized writer scheduler. [Same-session delivery](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L554-L561), [listing implementation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L822-L829).
- **Maintenance tradeoff:** shared state/planning helpers coexist with two substantial continuation/event adapters and two sidebar adapters. Compatibility breadth is real, while duplicated lifecycle logic increases the surface for adapter divergence. This is a structural inference, not a measured defect rate. [v1 continuation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1791-L2001), [v2 setup and continuation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2406-L2859), [TUI adapters](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/tui.ts#L536-L628).

## 2. What reliability guarantees, limits and cancellation behavior exist?

### Takeaway
The implementation has meaningful durability and race-avoidance mechanisms, not merely a repeated prompt. Its guarantees remain bounded by an in-process JSON mutation queue, heuristic progress/error classification and host lifecycle delivery; durable goal state is not a durable external scheduler. [Mutation queue](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L521-L590), [continuation state machine](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1791-L2001).

### Cited Findings
- **Persistence durability:** default location is XDG data home / Windows APPDATA / `~/.local/share`, under `opencode-goal-plugin/goals.json`, with an environment override. Mutations read, change and rewrite the JSON through an in-module promise queue. Writes use exclusive UUID temp files, mode `0600`, file fsync, rename, best-effort chmod and parent-directory fsync; known unsupported directory-sync errors are tolerated. Windows transient rename failures receive three bounded attempts. [Path](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state-path.ts#L1-L10), [queue/write](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L486-L590), [atomic implementation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/atomic-write.ts#L178-L278).
- **Recovery is deliberately selective:** boundary whitespace/BOM/NUL padding is tolerated; an all-padding file becomes empty state and nonempty padding can be preserved in a quarantine file before mutation. Other invalid JSON/schema state fails decoding instead of silently resetting everything. Recovery checks whether the original file changed before overwrite when quarantine succeeded. Do not generalize this to automatic repair of arbitrary corrupt JSON. [Parsing/decoding](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L398-L446), [quarantine and mutation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L453-L590).
- **Continuation reservation and deduplication:** one active continuation per session in a local Set, local scheduled timers, continuation epochs, goal/attempt IDs, persist-before-send reservation, post-await checks and rollback protect against duplicate idles, replacement/disposal races, busy/native-retry collisions and budget consumption for cancelled-before-delivery attempts. Delivery alone does not clear a failure episode; actual substantive assistant/tool progress resolves it. [Runtime structures](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1535-L1579), [delivery/races](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1876-L1985), [persistent attempt transitions](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1399-L1544), [tool correlation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1565-L1597).
- **Restart scope:** pending attempts/failures persist. An unstarted attempt not delivered by the current instance becomes eligible for unresolved-failure handling after 30 seconds, but only when the continuation path is invoked. Timers and busy/retry/ownership markers are local memory. V2 rebuilds task deferral from locally owned goals' transcripts and awaits recovery before continuation; failures fall back to live observations. Recovery iterates `getAllGoals().goals`, whose listing is capped at 50. [Stale attempt](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L603-L617), [runtime structures](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1535-L1555), [restart replay](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3503-L3530), [list cap](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L822-L829).
- **Provider/transport failure policy:** default failure ceiling is three. Regex-recognized network/transport errors retry after the remaining minimum continuation interval; abort/interrupt strings are excluded. Non-transport provider/configuration prompt errors roll back the reservation and log rather than consuming the transport-failure ceiling or retrying automatically. Native host retry episodes suppress competing plugin recovery. V2 terminal non-transport execution failure additionally suppresses future local autonomy. [Defaults/classification](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L84-L98), [classification](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L570-L600), [prompt errors](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1955-L1994), [native retry](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2301-L2326), [v2 terminal failure](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3056-L3102).
- **Task deferral:** defaults to enabled, with a 900-second task-block ceiling and one-second fallback retries. Running children and unreconciled terminal task results block parent continuation; expired records stop blocking. V1 optionally queries live children/status; v2 recovers from transcripts because its context lacks the live query used by v1. The timeout chooses liveness over indefinite waiting; it is not a proof that the child actually finished. [Defaults](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L84-L94), [blocking/live query](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L835-L890), [deferral scheduling](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1823-L1846), [v2 replay rationale](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3503-L3524).
- **Budgets:** defaults are 25 automatic continuation attempts and a three-second minimum interval. Optional token and active-duration limits transition state to `budgetLimited`/`usageLimited` and reserve one final wrap-up prompt. Token accounting uses observed cumulative sources with rebasing; fallback text estimation is `ceil(chars/4)`. Limits are checked through observation/reservation paths, not an OS-level kill timer. Watchdog rescues are uncharged to the auto-turn budget and deliberately do not arm no-progress evaluation. [Defaults/options](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L45-L98), [accounting](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1247-L1318), [limits/time](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1600-L1649), [estimate](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1681-L1683), [watchdog semantics](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1671-L1692).
- **Progress detection is heuristic:** continuation completion counts a low-progress turn when output tokens are positive but below a threshold and the summarized text has not changed; defaults are 50 tokens and two low-progress turns. Ordinary observations do not increment that counter. Substantive changed assistant text and successful non-read-only tool output are transport-health signals, not independent correctness evidence. [Defaults](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L181-L190), [assistant detection](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1322-L1395), [tool signals](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2209-L2227).
- **Pause/stop/clear/host abort:** pause preserves a resumable goal; explicit stop cancels it; clear archives and removes it. `stopAutonomy` invalidates local epochs, timers and markers—it does not call a host session-abort API in that path. A named v1 `MessageAbortedError` cancels only an active goal; v2 `session.execution.interrupted` stops local autonomy and persists cancellation only for `reason === "user"`. Thus stopping continuation is distinct from terminating an already running host tool or process. Plan-agent goals start paused and cannot be resumed by that restricted agent. [Stop/clear](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1304-L1313), [local stop](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1571-L1579), [pause command](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2184-L2192), [host abort](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2270-L2279), [v2 interruption](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3042-L3054), [plan restriction](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1426-L1443).
- **V2 ownership and stream failure:** server-wide events are filtered by location/session ownership to prevent sibling plugin instances continuing the same goal. The event consumer logs and marks itself stopped if its stream ends unexpectedly; the inspected consumer does not reconnect. A pursuing `/goal` command detects that marker on its wait loop and pauses on a non-abort command-wait error. [Ownership](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2930-L2973), [consumer](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3532-L3550), [wait error](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L3311-L3341).

### Inferences
- **Atomic replacement is not cross-process serialization:** the inspected writer has an in-module promise queue but no interprocess lock or compare-and-swap around ordinary read-modify-write. Independent instances/processes sharing the file could still lose updates even when each resulting JSON file is individually atomic. V2 ownership avoids duplicate processing for a session, not every possible overlapping write to the shared file. This is a code-level risk, not a reproduced incident. [Queue and write](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L486-L590), [ownership rationale](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L2930-L2939).
- **Budget semantics are advisory at turn boundaries:** a long ongoing model/tool turn can exceed a token/time target before another observation/reservation changes goal status; wrap-up itself is additional work. This follows from the inspected limit transitions and wrap-up prompt, not a measured overshoot benchmark. [Limits](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1600-L1649), [wrap-up policy](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/prompts.ts#L182-L214).
- **Failure classification trades simplicity for coverage:** regex detection can miss or misclassify provider-specific errors; repetitive-but-changing prose can also look like progress. These are limitations of the shown classifiers, not claims that tested provider failures are broken. [Error classifier](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L570-L587), [progress classifier](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1327-L1390).

### Gaps
- No crash, power-loss, interprocess-contention, real-provider outage or long-run soak experiment was executed. Observations above are static source findings and explicit inferences.
- No promise of exactly-once prompt execution across host/process crashes was established. The code persists intent and attempts rollback, but the remote host prompt call and local JSON commit are separate operations.
- Restart survival of records is established; automatic restart of every pre-existing idle goal without a subsequent host event was not established.

## 3. How strong are evaluation, review, tests and v1/v2 compatibility?

### Takeaway
The strongest correctness machinery is a revisioned plan with immutable completion criteria and required textual evidence/verification, backed by real regression tests and a real-host v2 smoke fixture. Completion itself remains an agent assertion subject to structural validation, rather than an independently executed acceptance check or separate reviewer verdict. [Completion path](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/server.ts#L1405-L1423), [state guard](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1108-L1147), [CI](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/.github/workflows/ci.yml#L15-L84).

### Cited Findings
- **Hard structural checks:** planned task completion requires evidence; phase completion requires all tasks completed and phase verification; at most one task/phase may be in progress, and phases advance in order. Overall completion rejects unfinished phases and requires nonempty evidence. With no plan, the overall evidence requirement still applies but there is no phase gate. [Plan validation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/goal-plan.ts#L55-L98), [completion](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L1108-L1147), [text validation](https://github.com/prevalentWare/opencode-goal-plugin/blob/9c52be63da06829d55e3e0b7a6580223312765b1/src/state.ts#L593-L612).
- **Plan mutation protection:** expected revision and goal ID reject stale edits; completion criteria cannot be changed within an existing plan. Removing/changing unfinished scope or reopening completed work requires revisit evidence, while completed IDs/descriptions/history are preserved. Compact plan operations and summary views reduce repeated full-plan payloads.
